## 3. 核心实现

### 3.1 ROS 单例
`ROS::instance()` 使用函数内局部静态对象，C++11 起其初始化由编译器保证线程安全。构造函数私有、拷贝构造与赋值运算符删除，确保全局唯一。

### 3.2 双映射表
核心维护两张 `unordered_map<string, vector<...>>`：
- `m_publishers`：话题 → 发布者列表
- `m_subscribers`：话题 → 订阅者列表

另用 `m_allNodes` 支持全局遍历关闭，`m_registeredNames`（`unordered_set`）按节点名去重，实现「重复节点注册」检测。

### 3.3 异步消息转发
`ROS::publish()` 不直接调用订阅者，而是为每个目标订阅者创建一个 `std::thread`，按值捕获 `Message` 副本后执行 `Subscriber::receive()`，`publish()` 随即返回——发布过程不等待订阅者，满足异步通信要求。所有派发线程被保存在 `m_dispatchThreads` 中，`shutdownAll()` 时统一 `join()`，避免 `std::terminate`。

### 3.4 时间戳生成
`Message` 构造时用 `std::chrono::system_clock::now()` 取当前时间，经 `to_time_t` 转换后，Windows 下用 `localtime_s`、其他平台用 `localtime_r` 得到本地时间，再用 `std::put_time` 格式化为 `YYYY-MM-DD HH:MM:SS`。

### 3.5 异常体系
```
std::runtime_error → ROSException → { NodeException, TopicException, MessageException }
```
所有非法输入都在最早可检测的位置抛异常：Node 构造函数查空名、Publisher/Subscriber 构造函数查空话题、Message 构造函数查空内容、ROS 注册查重、ROS 转发查话题存在性。`main()` 最外层用 `try-catch` 兜底，保证进程不崩溃。

### 3.6 分级日志
`Logger` 单例提供 `INFO / WARN / ERROR` 三级输出，内部 `std::mutex` 保证多线程日志不交叉；`enableFileLog("ros_simulation.log")` 后同步追加写入文本文件，满足「日志持久化」加分项。

## 4. 编译与运行

1. 用 Visual Studio 打开 `RosSimulation.sln`。
2. 工具栏选择 `Debug | x64`（或 `Release | x64`）。
3. 右键 `RosSimulation` →「设为启动项目」，按 `F5` 运行演示程序。
4. 右键 `RosSimulationTests` →「设为启动项目」，按 `F5` 运行测试；全部 `[PASS]` 且 `Failed: 0` 即通过。

程序会在当前工作目录生成 `ros_simulation.log`，记录本次运行的全部日志。

## 5. 设计权衡与改进方向

- **裸指针 vs 智能指针**：节点由 `main()` 拥有并保证先于 ROS 关闭完成前不析构，ROS 仅作观察者，故使用裸指针。若改成 `shared_ptr`/`weak_ptr` 可进一步避免悬垂指针。
- **线程 vs 消息队列**：当前每个订阅者一个线程，实现直观；节点或消息量增大时，可改为单一分发线程 + 阻塞队列的生产者-消费者模型。
- **可扩展方向**：模板化 Message 支持任意载荷、增加服务/客户端同步调用、运行时动态增删节点、日志接入 spdlog 等。

## 6. 已知限制

- `ROS::shutdownAll()` 后 ROS 单例清空映射表，节点需重新 `init()` 才能再次注册。
- 演示程序的异步派发在 `shutdownAll()` 处集中同步，未做背压控制。
