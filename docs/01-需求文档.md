# ROS 节点通信系统 — 需求文档

> 项目：C++ 模拟 ROS 核心发布-订阅通信
> 版本：v1.0
> 日期：2026-11-16

## 1. 项目背景

ROS（Robot Operating System）是机器人领域主流的分布式通信框架，其核心是**基于话题（Topic）的发布-订阅通信模式**。本项目不依赖真实 ROS API，而是用 C++ 从零模拟其通信骨架，目的是检验面向对象设计、C++ 编码规范与工程化能力，并为后续比赛实战打基础。

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 节点 Node | 系统最小功能单元，分发布者与订阅者，每个节点有唯一名称 |
| 话题 Topic | 节点间通信的「通道」，发布者向话题发消息，订阅者从话题收消息 |
| 消息 Message | 通信数据载体，包含业务内容（字符串）与系统时间戳 |
| 发布者 Publisher | 向指定话题发布消息的节点 |
| 订阅者 Subscriber | 订阅指定话题并接收消息的节点 |
| 单例模式 | 保证 ROS 核心管理类全局只有一个实例 |

## 3. 功能性需求

### FR-1 节点管理
- FR-1.1 系统支持创建**多个**发布者节点与**多个**订阅者节点。
- FR-1.2 每个节点拥有唯一名称；名称为空或重复注册必须抛出语义清晰的异常，程序不得崩溃。
- FR-1.3 所有节点按「初始化 → 消息交互 → 关闭」的完整生命周期运行。
- FR-1.4 节点的初始化与关闭均输出对应日志。

### FR-2 话题与通信
- FR-2.1 发布者向指定话题发布消息，订阅者从指定话题被动接收消息。
- FR-2.2 同一话题下可存在多个订阅者；发布一次，全部订阅者都能收到。
- FR-2.3 发布者可连续发布消息，发布过程**不等待订阅者响应**（异步通信）。
- FR-2.4 ROS 核心维护「话题→发布者」与「话题→订阅者」两类映射关系。

### FR-3 消息
- FR-3.1 消息封装字符串类型内容，仅提供只读访问接口。
- FR-3.2 消息自动生成 `YYYY-MM-DD HH:MM:SS` 格式的系统时间戳。
- FR-3.3 空消息发布必须抛出异常。

### FR-4 异常与健壮性
- FR-4.1 面对空节点名、重复节点注册、空消息发布、向不存在话题转发等非法输入/操作，程序禁止崩溃。
- FR-4.2 异常信息必须语义清晰，能定位具体节点/话题。

### FR-5 全局管理
- FR-5.1 ROS 核心采用单例模式，保证全局唯一实例。
- FR-5.2 提供统一关闭方法，遍历所有已注册节点并逐个执行关闭。

## 4. 加分需求（本项目全部实现）

- AR-1 自定义异常体系：`NodeException`、`TopicException`、`MessageException`，支持全局异常捕获。
- AR-2 分级日志：`INFO` / `WARN` / `ERROR`，同时输出到控制台与文本文件。
- AR-3 消息收发日志持久化到文本文件。
- AR-4 可扩展的自定义消息类型（预留传感器消息结构）。
- AR-5 结构化测试用例，覆盖正常场景、边界场景、异常场景。

## 5. 非功能性需求

- NFR-1 代码遵循严格 C++ 编码习惯，使用 C++17 标准，开启编译器警告。
- NFR-2 类职责单一，接口最小化，数据成员私有化。
- NFR-3 提供需求文档、架构设计文档、技术文档与用户手册。
- NFR-4 使用 Git 进行**增量开发**，每完成一个功能即提交一次，禁止一次性提交全部代码。

## 6. 验收标准

1. 编译生成可执行程序，运行后能看到完整的节点初始化、消息发布/接收、关闭日志。
2. 同一话题的多个订阅者均能收到消息。
3. 触发空节点名、重复注册、空消息、不存在话题转发时，程序不崩溃，输出清晰异常信息。
4. Git 提交历史体现逐步开发过程（不少于 8 次有意义的提交）。
5. 文档与测试用例齐全。
