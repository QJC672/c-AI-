# ROS 节点通信系统 — 架构设计文档

> 对应文档：《01-需求文档.md》
> 版本：v1.0
> 日期：2026-11-16

## 1. 总体架构

系统采用分层 + 单例核心的架构，分为四层：

```
┌─────────────────────────────────────────────┐
│  应用层      main.cpp（生命周期演示 / 异常演示） │
├─────────────────────────────────────────────┤
│  节点层      Publisher        Subscriber      │
│             (继承 Node)       (继承 Node)      │
├─────────────────────────────────────────────┤
│  核心层      ROS（单例）：注册 / 转发 / 全局关闭   │
├─────────────────────────────────────────────┤
│  基础设施层  Message  Logger  Exception        │
└─────────────────────────────────────────────┘
```

数据流向：`Publisher.publish() → 构造 Message → ROS.publish(topic, message) → 查找订阅者列表 → Subscriber.receive(message)`。

## 2. 类设计

### 2.1 Node（抽象基类）
- 私有成员 `m_name`（唯一节点名称），提供 `name()` 只读接口。
- 构造函数校验名称非空，否则抛 `NodeException`。
- 纯虚函数 `init()` / `shutdown()`，强制子类实现并输出日志。
- 虚析构函数，保证多态析构安全。

### 2.2 Publisher（发布者）
- 继承 `Node`，扩展私有成员 `m_topic`，提供 `topic()` 只读接口。
- `init()`：输出初始化日志，调用 `ROS::instance().registerPublisher(this)`。
- `publish(const std::string& data)`：校验数据非空 → 构造 `Message` → 输出发布日志 → 调用 `ROS::instance().publish(m_topic, msg)`。
- `shutdown()`：输出关闭日志。

### 2.3 Subscriber（订阅者）
- 继承 `Node`，扩展私有成员 `m_topic`，提供 `topic()` 只读接口。
- `init()`：输出初始化日志，调用 `ROS::instance().registerSubscriber(this)`。
- `receive(const Message& msg)`：输出包含消息内容与时间戳的接收日志（被动接收）。
- `shutdown()`：输出关闭日志。

### 2.4 Message（消息封装）
- 私有成员 `m_content`、`m_timestamp`，仅提供 `const` 只读接口。
- 构造函数记录 `std::chrono::system_clock::now()`，用 `std::put_time` 格式化为 `YYYY-MM-DD HH:MM:SS`。
- 空内容抛 `MessageException`。

### 2.5 ROS（核心单例）
- `ROS::instance()` 返回局部静态实例（C++11 起线程安全），构造/析构私有，禁止拷贝赋值。
- 双映射表：
  - `unordered_map<string, vector<Publisher*>> m_publishers`
  - `unordered_map<string, vector<Subscriber*>> m_subscribers`
  - 另设 `m_allNodes` 便于全局遍历关闭。
- `registerPublisher/registerSubscriber`：校验指针非空、按名称去重，更新映射表。
- `publish(topic, msg)`：校验话题存在订阅者，否则抛 `TopicException`；对每个订阅者派发消息。
- 异步通信：使用 `std::thread` 为每个订阅者创建独立派发任务，存入线程池向量，`shutdownAll()` 时统一 `join()`。
- `shutdownAll()`：先 join 所有派发线程，再遍历 `m_allNodes` 调用 `shutdown()`，最后清空映射表。

### 2.6 Logger（日志器，加分项）
- 单例，提供 `log(LogLevel, module, message)`。
- 级别 `INFO / WARN / ERROR`，输出到 `std::cout`。
- 可调用 `enableFileLog(path)` 将日志同步写入文本文件（追加模式）。
- 内部 `std::mutex` 保证多线程日志输出不交叉。

### 2.7 异常体系（加分项）
```
std::runtime_error
      └── ROSException
            ├── NodeException
            ├── TopicException
            └── MessageException
```

## 3. 关键流程时序

```
main                 Publisher          ROS            Subscriber
 │                      │                │                  │
 │── construct ────────>│                │                  │
 │── init() ───────────>│── register ───>│                  │
 │                      │                │<──── register ───│<── init()
 │── publish(data) ────>│── Message()    │                  │
 │                      │── publish(t,msg)                │
 │                      │                │── async ────────>│── receive(msg)
 │── shutdownAll() ─────────────────────>│── shutdown() ───>│
```

## 4. 并发与生命周期设计

- 发布者调用 `publish()` 后立即返回，不等待订阅者处理，满足异步要求。
- 派发线程在 `ROS::shutdownAll()` 中统一回收，避免 `std::terminate`。
- 节点对象生命周期由 `main()` 管理，必须**先**调用 `shutdownAll()` **再**销毁节点对象。
- `Logger` 与 `ROS` 的映射表访问均加锁，保证线程安全。

## 5. 异常策略

| 异常场景 | 抛出异常 | 处理位置 |
|---|---|---|
| 节点名为空 | NodeException | Node 构造函数 |
| 节点重复注册 | NodeException | ROS::register* |
| 话题名为空 | TopicException | Publisher/Subscriber 构造函数 |
| 向无订阅者话题发布 | TopicException | ROS::publish |
| 消息内容为空 | MessageException | Message 构造函数 / Publisher::publish |

`main()` 最外层使用 `try-catch` 全局捕获 `ROSException` 与 `std::exception`，以 `ERROR` 级别记录日志，保证进程不因异常直接终止。
